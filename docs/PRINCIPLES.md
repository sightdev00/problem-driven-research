# 目标与原则

目标：开发 GitHub 仓库，从论文、博文或工程现象进入，核实并定义研究问题，调查全球相关团队的成果与可迁移机制，结合工程实验不断更新判断，形成可追溯的研究成果。

八项原则：

1. 不重复造轮子，优先使用已有工具和接口。
2. 遵循奥卡姆剃刀，只增加必要结构。
3. 遵循第一性原理，深入基础机制，抓住主要矛盾。
4. 兼顾仓库展示与可维护性。
5. 领域严格限定；人可以切换领域，运行时锁定领域版本。
6. 区分现象、解释、假设和证据，主动保留反证与未知。
7. 根据新证据持续更新判断，必要时重定义问题。
8. 问题正确性优先，避免高效自动化放大错误问题定义。

## 问题定义

问题是可更新的模型，包含原始观察、观测链、领域边界、可操作化的概念、竞争假设及其区分性预测、决策背景、人工确认和重新定义条件。专家 Skill 作为方法论先验，不作为本问题的事实证据。

## 问题分析

分析按七组原则展开：机制与因果；优先级与收敛；实验素材与人机交接；证据质量与稳健性；外部证据、反例与迁移；系统层级与分析单位；结论版本和持续更新。分析子问题时，以与最终目标的因果关联为第一排序依据，再比较区分能力与成本。
